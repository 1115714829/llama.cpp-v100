## 实测数据

当前版本 2.0.1.1：6 × V100-16GB、Q8_0 + DFlash2 F16、上下文 262144，约 20 万 token 真实代码预填充 2187 tok/s、吐字 124.5 tok/s；约 1.6 万 token 预填充 2786 tok/s、吐字 152.7 tok/s（温度 0、不开思考，新起服务、前缀不命中缓存）。与 2.0.1 同场对比无退化，温度 0 输出相同，每卡显存相同。

- 其他配置（4 卡、2/3/5 卡与 Q4 配置、`-ub` 对比、524288 上下文、多路并发、多模态）最近一次完整实测在 1.1.1，见 [1.1.1 实测归档](27b-results-1.1.1.md)。
- 测试条件与历次版本的全部数据见[历次实测数据](benchmarks.md#2011)。

草稿模型官方只发布 BF16、Q8_0、Q4_K_M 三种 GGUF；推荐的 F16（V100 没有 BF16 硬件支持）要用本项目编译出的 `llama-quantize` 转换一次。先按下一节编译，然后一条命令完成下载和转换：

```bash
scripts/v100-get-models.sh            # 默认从魔搭下载到 ./models
scripts/v100-get-models.sh -s hf      # 改用 Hugging Face
```

脚本下载目标模型和草稿模型（支持断点续传，已下载的文件自动跳过），再把草稿转成 `Qwen3.8-27B-DFlash2-F16.gguf`；`-d` 指定模型目录，`-q` 指定 `llama-quantize` 的路径，`-h` 查看用法。视觉模块不在脚本里，需要时单独下载。已经自己下载好时只做转换：`./build/bin/llama-quantize Qwen3.8-27B-DFlash2-BF16.gguf Qwen3.8-27B-DFlash2-F16.gguf F16`。单个文件也可以用魔搭直链断点续传：`wget -c https://modelscope.cn/models/<仓库>/resolve/master/<文件>`。

## 编译

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=70 -DGGML_CUDA_FA=ON -DGGML_CUDA_GRAPHS=ON \
  -DGGML_CUDA_NCCL=ON -DNCCL_INCLUDE_DIR=/path/to/nccl/include -DNCCL_LIBRARY=/path/to/nccl/lib/libnccl.so.2
cmake --build build -j --target llama-server llama-quantize
```

多卡张量并行需要 NCCL，编译器用 GCC 12 或更新的版本。网页界面随源码自带（`tools/ui/dist`），编译时直接嵌入程序，整个编译过程不需要联网，也不需要 Node.js；只有改了界面源码才需要重新构建界面，见 [AI 部署指引 · 编译参数](ai-deploy.md#编译参数自己编译时)。GitHub 上每次推送都会自动按 sm_70 编译检查；发布版本附带 x86_64 Linux 的预编译程序（CUDA 12，见 Releases 页面），POWER9 等其他平台按上面的命令自行编译。

## 启动参数

AC922 上用 `numactl --membind=0,8` 把主机内存限定在有 CPU 的 NUMA 节点（AC922 把 GPU 显存并入系统内存，不限定时页缓存可能占用显存；节点号用 `numactl --hardware` 查看，带 CPU 的节点就是主机内存节点）；普通 x86 服务器去掉这一段。各参数做什么、怎么选见 [AI 部署指引 · 参数说明](ai-deploy.md#4-参数说明)。

### A. 6 卡，上下文 262144

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5 numactl --membind=0,8 ./build/bin/llama-server \
  -m ./models/Qwen3.8-27B-Q8_0.gguf -ngl 999 \
  --split-mode tensor --tensor-split 1,1,1,1,1,1 \
  -c 262144 -np 1 -fa on -ctk q8_0 -ctv q8_0 -b 2048 -ub 2048 \
  --model-draft ./models/Qwen3.8-27B-DFlash2-F16.gguf \
  --spec-type draft-dflash --spec-draft-n-max 7 \
  --host 127.0.0.1 --port 8080 --metrics
```

### B. 4 卡，上下文 262144

命令 A 改 `--tensor-split 1,1,1,1` 与 `CUDA_VISIBLE_DEVICES`：AC922 上用 `0,1,3,4`（两颗 CPU 各两张）；x86 写 `0,1,2,3` 并去掉 `numactl` 一段。其余不变。

### 在 A / B 的基础上改

- **上下文 524288（YaRN）**：`-c 524288`，并加 `--rope-scaling yarn --rope-scale 2 --yarn-orig-ctx 262144 --override-kv qwen35.context_length=int:524288`；YaRN 设置对所有长度都生效。
- **多路并发**：`-np N`，每路上下文 = `-c` ÷ N（例如 4 卡 `-c 262144 -np 2` 每路 131072；6 卡两路各 262144 用 524288 的设置加 `-np 2`）。提示词处理按顺序排队，后面几路的首字要等前面的处理完，全部完成的总时间与依次处理差不多；好处是先开始吐字的请求不会被后来的长提示词卡住。`--prefill-pace`（默认 30，0 或 100 为不限流）调大，后来请求的首字更快、正在吐字的请求更慢。单个 Agent 要开满长上下文时仍用 `-np 1`。
- **多模态**：加 `--mmproj ./models/mmproj-F16.gguf`，处理视频再加 `--video-ffmpeg-dir <ffmpeg 所在目录>`。请求走 OpenAI 兼容的 `/v1/chat/completions`：图片用 `image_url`，视频用 `input_video`（或 `video_url`，默认每秒取 4 帧），PDF 由客户端把每页渲染成图片发送。视觉模块默认分到主模型使用的全部 GPU；显存不够时用 `--no-mmproj-offload` 放 CPU（处理图片、视频会慢很多），或 `-mmdev <设备>` 只放一张卡。
- **其他卡数**：改 `CUDA_VISIBLE_DEVICES` 与 `--tensor-split`（几张卡写几个 1）；各卡数能开的最高上下文见 [AI 部署指引 · 选模型与配置](ai-deploy.md#2-选模型与配置)。
- **Q4 配置**：`-m ./models/Qwen3.8-27B-UD-Q4_K_M.gguf -ctk q4_0 -ctv q4_0`。2 卡只能用 Q4 配置（Q8_0 主模型放不下 2 张 16 GB 卡），2 卡开 262144 时草稿换 `./models/Qwen3.8-27B-DFlash2-Q4_K_M.gguf`。
- **采样**：模型卡推荐思考模式 temperature 1.0、top_p 0.95、top_k 20、min_p 0（`--temp 1.0 --top-p 0.95 --top-k 20 --min-p 0`）；非思考模式 temperature 0.7、top_p 0.8、top_k 20、presence_penalty 1.5（`--temp 0.7 --top-p 0.8 --top-k 20 --presence-penalty 1.5 --chat-template-kwargs '{"enable_thinking":false}'`）。加在命令末尾作为服务默认，请求里带的采样参数优先。`top_k` 不超过 64、且只用 top-k、top-p、min-p、temperature 与 repeat / presence / frequency penalty 时速度最快；用 DRY 等其他采样器或 `top_k` 更大时，吐字会变慢。

## Docker

镜像只包含 sm_70（V100）代码，基于 CUDA 12.4.1，内含 NCCL、ffmpeg（视频输入）、numactl 和 `llama-quantize`；宿主机需要 NVIDIA 驱动 550 或更新。镜像发布在 GitHub Container Registry，同一个标签同时包含 linux/amd64（x86_64 + V100，用 NVIDIA Container Toolkit 的 `--gpus all`）与 linux/ppc64le（仅 IBM Power AC922，用 `.devops/v100-ac922-cdi.sh` 生成的 CDI 描述，`--device nvidia.com/gpu=all`），`docker pull` 时按宿主机架构自动选择。入口是 `llama-server`，镜像名之后的参数直接传给它（路径改成容器内的 `/models/...`）。

### C. Docker，6 卡，AC922（podman，`podman-docker` 提供同名的 `docker` 命令）

```bash
sudo dnf install -y podman podman-docker
sudo bash .devops/v100-ac922-cdi.sh        # 生成 /etc/cdi/nvidia.yaml，只需执行一次；驱动升级后重新执行
docker run -d --name llama-v100 --device nvidia.com/gpu=all --ipc=host --ulimit memlock=-1 \
  -e LLAMA_NUMA_MEMBIND=0,8 \
  -p 8080:8080 -v <模型目录>:/models \
  ghcr.io/1115714829/llama.cpp-v100:2.0.1.1 \
  -m /models/Qwen3.8-27B-Q8_0.gguf -ngl 999 \
  --split-mode tensor --tensor-split 1,1,1,1,1,1 \
  -c 262144 -np 1 -fa on -ctk q8_0 -ctv q8_0 -b 2048 -ub 2048 \
  --model-draft /models/Qwen3.8-27B-DFlash2-F16.gguf \
  --spec-type draft-dflash --spec-draft-n-max 7 \
  --port 8080
```

### D. Docker，4 卡，x86

```bash
docker run -d --name llama-v100 --gpus all --ipc=host --ulimit memlock=-1 \
  -p 8080:8080 -v <模型目录>:/models \
  ghcr.io/1115714829/llama.cpp-v100:2.0.1.1 \
  -m /models/Qwen3.8-27B-Q8_0.gguf -ngl 999 \
  --split-mode tensor --tensor-split 1,1,1,1 \
  -c 262144 -np 1 -fa on -ctk q8_0 -ctv q8_0 -b 2048 -ub 2048 \
  --model-draft /models/Qwen3.8-27B-DFlash2-F16.gguf \
  --spec-type draft-dflash --spec-draft-n-max 7 \
  --port 8080
```

草稿模型转 F16 也可以用镜像里的 `llama-quantize`：

```bash
docker run --rm --entrypoint /app/llama-quantize -v <模型目录>:/models ghcr.io/1115714829/llama.cpp-v100:2.0.1.1 \
  /models/Qwen3.8-27B-DFlash2-BF16.gguf /models/Qwen3.8-27B-DFlash2-F16.gguf F16
```

- `<模型目录>` 写绝对路径；`--ipc=host`、`--ulimit memlock=-1` 是多卡运行需要的共享内存与锁页内存设置。只用部分 GPU 时，x86 写 `--gpus '"device=0,1"'`，AC922 写 `--device nvidia.com/gpu=0` 等；2 卡请用 Q4 配置。
- `-e LLAMA_NUMA_MEMBIND=<节点>` 让容器用 `numactl --membind=<节点>` 启动，只用于 AC922 这类把 GPU 显存上线为 NUMA 节点的机器（填有 CPU 的节点 `0,8`）；节点必须是 `numactl --hardware` 中存在的节点，否则容器启动即退出。不要用 `--cpuset-mems` 限定内存节点（会使容器内 CUDA 初始化失败）。
- 镜像默认设置 `LLAMA_ARG_HOST=0.0.0.0`，对外是否可访问由 `-p` 或 `--network host` 决定；对外服务时加 `--api-key-file /run/llama.apikey` 并挂载 `-v <密钥文件>:/run/llama.apikey:ro`。视频输入加 `--video-ffmpeg-dir /opt/tools/bin`（镜像内的 ffmpeg）。
- 不能访问 ghcr.io 时，从 Releases 页面下载镜像文件（`llama.cpp-v100-server-<版本>-<架构>.tar.gz`）用 `docker load -i <文件>` 导入，或在源码目录自行构建：`docker build -f .devops/v100-cuda.Dockerfile -t llama.cpp-v100:server .`。
